## 效果示例

下面三段都是真实播报，左边是常规读法，右边是观澜读法。

### 一 · 一整期让给一份文件

> **原文**：某日联播共 10 条，前 6 条是同一份党内文件的不同形态——说明全文、决定全文、单行本出版、学习反响、评论员文章、央视快评。

**常规读法**：很重要，规格很高。

**观澜读法**：30 分钟通常装 15–20 条大事。今天把六个位置给同一份文件，**这不是"重视"，是优先级排序的极端形态**。同主题用的文体越多、越交叉（文件+出版+评论+快评），说明它需要覆盖的读者越多。再往下一层：这份文件的定性来自全会公报（骨架），细节来自《决定》（操作），而《说明》里"确定议题的考虑"才是真正的动机自述——**公报没说的才是增量**。
　`方法 54 重复信号 · 58 排序即配置 · 72 文件层级法`

### 二 · 一句话里的权力结构

> **原文**：《决定》明确——执行"一把手"末位表态制；书记专题会议不得代替党委常委会作出决策；重大决策终身负责制；下级纪委至少每半年向上级纪委报告"一把手"履职情况。

**常规读法**：加强了对领导干部的监督。

**观澜读法**：这四句合起来在干一件事——**把"集中"这个最大漏洞装进可回查的程序**。末位表态改的是发言顺序（一把手最后说，别人才能不说违心话）；半年报告改的是信息通道（纪委不必等举报）；终身负责改的是时间成本（离任不算完）。判断的重点不是"更严了"，而是**治理的计价单位换了一代：从"人"（处理了多少）到"程序"（能不能回查）**。可验证的落点也在这里：条例修订稿什么时候出。
　`方法 72 文件层级法 · 成本-程序转换`

### 三 · 一个被当成数据的政策工具

> **原文**：前三季度社会物流总费用与 GDP 比率降至 13.8%，全社会物流成本节约超 2100 亿元。

**常规读法**：物流降本成效显著。

**观澜读法**：2100 亿 ≈ GDP 的 0.15%，**性质等同一次不需要财政出钱的减税**——在财政支出只增 1.0% 的年份里，这是最便宜的宏观刺激。所以它的政策地位远高于一条行业新闻：能替代增量财政的工具，会被反复使用。落点看三处：费用率能否降到 13.5%、铁路与水运货运占比、多式联运单证签发量。
　`方法 18 数据拆解法 · 40 准融资工具视角`

**这三段都不是"感觉"，每一条都挂得上编号，也都能被明天的新闻证伪。**

## 安装

观澜是一个纯 Markdown 的 Skill，没有依赖、不联网、不调模型接口。

```bash
git clone https://github.com/yt875148249-svg/guanlan-skill.git ~/.claude/skills/guanlan
```

只要你的 agent 支持 `SKILL.md` 目录规范（Claude Code / Hermes / Cursor / 任何能读目录的本地模型），放到它的 skills 目录即可。

<details>
<summary>手动安装 / 其他位置</summary>

- **Hermes**：放到 `~/.hermes/skills/guanlan/`（或在配置文件里加技能目录）
- **Claude Code**：放到 `~/.claude/skills/guanlan/`
- **任意 LLM 网页版**：不需要安装，把 `prompts/daily.md` 整段粘进去，再把当天的播报文字贴在后面

</details>

## 核心原理

观澜把「读新闻」拆成五层，每层都有可执行的判据，不是靠悟性：

| 层 | 回答什么 | 判据来源 |
|---|---|---|
| **层级** | 谁在说、说到哪一步 | S0–S6 六级：定调 → 落子 → 攻坚 → 验证 |
| **阶段** | 现在是承诺、执行，还是结账 | 13 个受控判断词，每条只能给一个 |
| **信号** | 哪句话变了、哪句话没出现 | 六类措辞信号 + 45 组实测差分 |
| **机制** | 为什么是它、为什么是现在 | 79 条方法库，逐条带操作化 |
| **传导** | 然后会到哪里 | 9 条全球传导链 + 18 条战略轴 |

### 和"看新闻学"有什么不同

三点区别，也是这个仓库存在的理由：

1. **判断必须挂编号**。说不出用了哪条方法，就降级为观察项——这挡住了 90% 的"感觉很像"。
2. **"没出现"和"出现了"同等重要**。拒答、沉默、不点名、静默期、该报没报，都是信号（方法 4/15/74）。
3. **判错要留档**。`references/06-failure-log.md` 记录真实误判和修正过程，包括被自己的数据打脸的那几次。

### 诚实边界

这套方法**做不到**的事，写在前面：

- 只有单日文本时，给不出措辞差分结论——硬做就是编造
- 「名词层」和「硬交付」的区别必须靠后续文本验证，当期只能标"待验证"
- 它判断的是**概率与结构**，不是事实认定，更不是内幕
- 它是**文本方法**：对没有落到文字里的东西（人事内情、未公开博弈）完全无效
- 没有第三方盲测。现有验证全部来自内部预判-兑现闭环，见 [成果](#成果)

## 技术架构

> 完整版见 [`references/07-architecture.md`](references/07-architecture.md)。这里回答三件事：**凭什么信、怎么讲得通、怎么积累**。

### 一 · 校验层：四道闸

判断之前先过闸。每道闸挡一类具体错误，全部来自真实翻车：

| 闸 | 挡住什么 | 规则 |
|---|---|---|
| **口径闸** | 盘中当收盘、时点混用 | 读数必须带**采集时点 + 口径**（盘中/收盘/期货近月/现货）；跨日只比同口径 |
| **来源闸** | 跨源混算放大误差 | 同一价位只允许**同序列**重算；两源背离时并列标注，只用同源日变化定方向 |
| **序列闸** | 冻结数据造出假趋势 | 连续 3 个交易日零变化＝**冻结**，停用其派生指标（利差/价差/比价） |
| **证据闸** | 把"揭牌"当落地 | 三级：表态 → 名词层（**必须标待验证**）→ 硬交付（签字文本/清单/生效日期/可罚条款） |

另外两道补闸，专门治"数字对、含义错"：

- **披露入口闸**：人事/处罚类必须多入口并采（公报 + 系统内通报 + 集中通报期）——单一渠道曾导致 **3.1 倍低估**
- **计划性闸**："释放/动用/投放"先分清是**计划执行节点**还是**临时新决定**——前者是进度披露，后者才是政策增量

### 二 · 逻辑层：可证伪回路

```
判断 → 登记判据 → 次日/到期核对 → 兑现 or 证伪 → 回写规则
                                          ├─ 兑现：方法保留
                                          └─ 证伪：进误判档案
```

三条硬约束：

1. **判断必须挂编号**（`方法 58`）。挂不上＝这是直觉，降级为观察项。编号让每条判断都能被指向具体规则及其失效条件。
2. **判据三要素齐全**：看什么 + 什么时候 + 什么算成立。写"关注政策落地"不算判据，写"三项条例修订稿年内是否公开征求意见"才算。
3. **证伪必须写进当期报告**，不许悄悄换掉旧判断；误判进档案，永久保留、不删不改。

再加一道内部一致性检查：每条核心判断进**互证表**，与既有推演对撞，标 `✅ 一致 / ⚠️ 分歧 / 🧩 补充`。**"分歧"是最值钱的一格**——要么旧推演该改，要么今天判断错了，两者都得处理，不能挂着。

### 三 · 知识层：提炼与归档

产出分两层存：**正文给人读，YAML 数据层给机器读**（条目六字段 + 跨库因果链四字段）。只有结构化的部分能被检索、聚合、回测——三个月后要问"所有标为『结账期』的条目后来兑现了多少"，自由文本答不了，YAML 可以。

```
每日产出
  ├─ 正文 ──────────────► 按日期归档
  └─ YAML 数据层
        ├─ 条目 ─────────► 主题索引（52 词，受控词表）
        ├─ 因果链 ───────► 因果链索引（503+ 条，带判据与验证状态）
        └─ 措辞信号 ─────► 措辞变更档案（45 组，按类别）
```

**提炼不是摘抄，是四级筛选**：

```
个案（一次真实文本）→ 差分（前后原句 + 排除假变化）→ 方法（操作化 + 边界 + 判据）→ 复现（换文本还能用吗）
```

进不了「复现」这一级的，只能留在差分表里，不进方法库。

**版本化管理**：月度蒸馏以上月全部日报为输入，产出方法增量、差分增量、轴变更与新版本框架，**每次都可回退上一版**。目前迭代到第六版，六个历史版本全部保留。

**退役规则比新增规则更重要**：轴连续 60 天无新节点即退役；方法被证明有边界就限定适用范围，不删除；主题词禁止同义并存。宁可 18 条轴管用，不要 40 条轴摆着。

### 四 · 流水线（实际执行顺序）

```
原文文本
  │
  ├─ ① 切条目：数条数、记排序、标语体异常（全文播发/单行本/评论员/快评/系列第N期）
  ├─ ② 定位：S0–S6 层级 + 13 判断词之一
  ├─ ③ 扫描：时间/空间/主体/工具/目标/约束/金融/元信号 八维
  ├─ ④ 检测：六类信号 + 措辞差分 + 过四道闸 + 挂方法编号
  └─ ⑤ 成稿：原文要点（事实）+ 判断（机制）+ 互证表 + 观察清单
        │
        └─ 观察清单 → 次日核对 → 兑现/证伪 → 回写
```

**第 ⑤ 步的回路是整个系统的核心：没有验证的解读只是评论。**

## 成果

蒸馏不是比喻，是数字。这套方法已经把一路真实语料跑完：

| 项 | 数量 | 说明 |
|---|---|---|
| 已处理播报原文 | **1,510 份** | 2022.09 起连续 |
| 已完成解读 | **323 篇** | 每篇 5–8 条，含原文要点 + 判断 |
| 方法库 | **79 条** | 每条带操作化步骤与实例 |
| 措辞差分实例 | **45 组** | 前后表述对照 + 意图判定 |
| 因果链索引 | **503+ 条** | 跨库可追溯，带验证判据 |
| 传导链 / 战略轴 | **9 / 18 条** | 全球传导 + 长期主线 |
| 成稿自检 | **24 条** | 缺一条不许定稿 |

**关于保真度**：这里不提供评分卡。有评分卡的前提是有人做过盲测，我们没做过，就不写。现有质量证据是三种：①每条判断挂方法编号，可被审稿推翻；②预判登记后逐日核对兑现/证伪；③每次判错都进 `06-failure-log.md`，不删。

## 背后的故事

《新闻联播》被当成"宣传"太久了——要么全信，要么全不信。但它其实是一份**意图文本**：30 分钟装下了这个系统希望你知道的东西，以及它希望你以为它没在意的顺序。

"观澜"取自"观水有术，必观其澜"：看一条河，不看水面漂着什么，要看水势转折的地方。转折处就是措辞的变化、排序的调整、该出现而没出现的那句话。

这套框架原来是私人笔记，跟着每天的播报长：方法从 12 条长到 79 条，差分从个位数长到 45 组，判错一次就修一次规则。后来发现它有个可迁移的性质——**任何高密度、低冗余、字字有权的官方文本，都能用同一套方法读**。所以把它拆出来。

它不预测。它只是让你在别人看到"发生了什么"的地方，看到"为什么是它、为什么是现在"。
