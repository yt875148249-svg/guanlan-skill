# 技术架构

> 方法论回答"怎么看"，架构回答"凭什么信、怎么不漏、怎么不腐化"。
> 这一层是可工程化的部分：**四道校验闸 + 一条可证伪回路 + 一套版本化知识库**。

---

## 0. 全景

```
原始播报文本（脏：OCR 断字、口语、重复）
        │
  ①  切分与结构化 ──────────────► 条目表（六字段）+ 跨库因果链（四字段）
        │                                    │
  ②  四道校验闸 ◄───────────────────────────┘
        │  口径闸 · 来源闸 · 序列闸 · 证据闸
        │
  ③  判断生成（证据等级 → 判据 → 观察项）
        │
  ④  次日核对 ──► 兑现 / 证伪 ──► 回写：方法库 · 差分表 · 误判档案
        │
  ⑤  归档与蒸馏（月）──► 主题索引 · 因果链索引 · 措辞档案 ──► 框架新版本
```

关键设计：**①和②是机器活，③是判断活，④⑤是制度活**。四步各自独立可查，任何一步出错都能定位到具体环节，而不是笼统地说"判断错了"。

---

## 1. 数据层：从脏文本到结构化

### 1.1 输入不做美化

输入是节目文字稿（OCR/转录），含断字、错字、口语残句。**处理原则：不修原文，只切分。** 修改原文会让后续所有差分失去对照基准——你改了一个错字，就再也分不清"这个词变了"还是"你改的"。

### 1.2 结构化：正文与数据层分离

每条新闻产出两组东西：

| 层 | 内容 | 用途 |
|---|---|---|
| **正文** | 原文要点 + 判断（人读） | 交付、阅读 |
| **数据层** | YAML：条目六字段 + 跨库因果链四字段（机器读） | 聚合、索引、回测 |

条目六字段：`序号 / 主题（受控词表）/ 层级（S0–S6）/ 事件（≤60字）/ 判断（13 词之一）/ 关键词（3–5 具体名词）`

跨库因果链四字段：`上游 / 下游 / 类型 / 推演逻辑（必须含判据）`

**为什么必须结构化**：只有结构化的部分才能被检索和统计。三个月后你要问"去年所有标为『结账期』的条目，后来兑现了多少"——自由文本答不了这个问题，YAML 可以。

### 1.3 受控词表：让数据可比

- 主题词固定 52 个（不合规则即纠错，禁止自造同义词）
- 判断词固定 13 个（每条只能给一个）
- 层级固定 6 级

**受控词表的意义不是规范，是可聚合性。** 词一旦自由，历史数据就废了——"新质生产力"和"未来产业"混用三个月，你的趋势统计就全错。

## 2. 校验层：四道闸

每道闸都是"用一个具体规则，挡住一类具体错误"。全部来自真实翻车。

### 闸 1 · 口径闸（时间戳强制）

| | |
|---|---|
| **问题** | 同一读数在不同时点完全不同，混用会得出反向结论 |
| **规则** | 任何价格/利率/指数必须同时记录 **采集时点 + 口径**（盘中 / 收盘 / 期货近月 / 现货）；跨日比较一律同口径 |
| **违规处理** | 缺口径的读数不进结论，只进备注 |

> 真实事故：把盘中价标成"日K收盘"，据此判断"继续下行"。次日核对交易所收盘，方向反了。

### 闸 2 · 来源闸（同序列重算）

| | |
|---|---|
| **问题** | 不同数据源的绝对价有系统偏差，用 A 的现价减 B 的历史价，涨跌幅会被放大一个数量级 |
| **规则** | 同一价位只允许**同序列**重算；两源背离时**并列标注**，只用同源日变化定方向 |
| **违规处理** | 已发布的跨源结论作废并显式更正，不静默替换 |

> 真实事故：坏值导致"油价 −5.41%、价差压缩 33.2%"。同源重算为 −1.04%、价差**扩大** 0.45。方向和幅度同时错。

### 闸 3 · 序列闸（冻结判定）

| | |
|---|---|
| **问题** | 数据源冻结时读数不变，所有派生指标（利差、价差、比价）都是假的 |
| **规则** | 关键指标**连续 3 个交易日零变化 = 冻结**，标红并停用其派生指标 |
| **违规处理** | 冻结期只能输出"方向不明"，不能输出"走阔/收窄" |

### 闸 4 · 证据闸（交付形态分级）

| 等级 | 特征 | 允许的表述 |
|---|---|---|
| L0 表态 | 只有"支持/欢迎/愿同…" | "表态"，不得推演结果 |
| L1 名词层 | 有共识、有机制名、无条款 | **必须标"待验证"** |
| L2 硬交付 | 签字文本 / 清单 / 生效日期 / 可罚条款 | 可判"落子/兑现" |

**这一闸最常拦住的错误**：把"揭牌""成立""签署备忘录"当成落地。**有没有罚则、有没有生效日、有没有清单，才是交付的分界。**

### 补闸 A · 披露入口闸（多入口并采）

人事、处分、处罚类数据，单一渠道会系统性漏数。

> 真实事故：一份台账按"公开通报"统计，得出"将追认 11 人"，实际 34 人——**低估 3.1 倍**。原因：另一系统的处分走独立披露入口，不在常规通报里。

规则：多入口并采（公报 + 系统内通报 + 集中通报期），每行数据必须能说出**披露入口**。

### 补闸 B · 计划性闸（执行节点 vs 新决定）

| 类型 | 识别 | 政策含义 |
|---|---|---|
| 计划执行节点 | 有原始计划、进度表、总量约束 | 进度披露，方向未变 |
| 临时新决定 | 无前置计划、一次性公告 | 真实增量 |

> 真实事故：把"追加释放储备"读成"动用最后缓冲"，核对原计划发现是 4 亿桶方案已执行 80% 的节奏安排。

## 3. 逻辑层：怎么保证"讲得通"

### 3.1 判断必须可追溯（方法编号）

每条判断后面挂编号（`方法 58`）。这条规则的作用不是装饰，是**强制判断落进已有的检验框架**：

- 挂得上 → 该方法的适用条件、已知反例都可查
- 挂不上 → 说明这是直觉，降级为观察项

**它把"我觉得"变成了"用第 N 条规则，该规则的失效条件是 X"。**

### 3.2 判据三要素

一条判断要能成立，判据必须写全：

```
看什么（可核查对象）+ 什么时候（期限）+ 什么算成立/证伪
```

不合格："后续关注政策落地情况"
合格："三项条例修订稿是否在年内公开征求意见；未出＝程序化判断不成立"

### 3.3 可证伪回路（架构的核心）

```
判断 → 登记判据 → 次日/到期核对 → 兑现 or 证伪 → 回写
                                                    ├─ 兑现：方法保留，可加权重
                                                    └─ 证伪：进误判档案，改规则
```

三条规定：

1. **观察清单每条都必须能被打脸**（写"看什么"，不写"关注一下"）
2. **证伪必须显式写进当期报告**，不许悄悄换掉旧判断
3. **误判档案永久保留**，不删、不改历史结论

### 3.4 内部一致性检查（互证表）

每条核心判断进一张表，与既有推演对撞：

| 判断 | 既有推演 | 印证 |
|---|---|---|
| … | … | ✅ 一致 / ⚠️ 分歧 / 🧩 补充视角 |

**"⚠️ 分歧"是这张表最有价值的一格**——它意味着要么旧推演该改，要么今天的判断有误，两种都必须处理，不能挂着。

### 3.5 逻辑性的四条硬约束

| 约束 | 具体含义 |
|---|---|
| 不写动机写措辞 | "从X改为Y，含义是Z" 可核对；"领导不想…"不可证伪 |
| 无对照不做差分 | 单日文本只做结构分析，不做跨期结论 |
| 三种降级必须分清 | 效果不佳型 / 额度耗尽型 / 目标重定义，含义完全不同 |
| 结论带置信度 | 事实 / 推断 / 假设 三层分开标注 |

## 4. 知识层：怎么提炼、怎么归档、怎么不腐化

### 4.1 归档单元与三层索引

```
每日产出
  ├─ 日报正文（人读）───────────► 04 类：按日期归档
  └─ YAML 数据层（机器读）
        ├─ 条目 ───────────────► 主题索引（52 词，按议题聚合）
        ├─ 跨库因果链 ─────────► 因果链索引（503+ 条，带判据与验证状态）
        └─ 措辞信号 ───────────► 措辞变更档案（45 组，按类别归档）
```

三层的分工：

| 索引 | 回答的问题 | 规模 |
|---|---|---|
| 主题索引 | 这个议题三个月来怎么演进的？ | 52 个主题 |
| 因果链索引 | 这条判断有没有前身？判据兑现了没？ | 503+ 条 |
| 措辞变更档案 | 这句话以前怎么说的？ | 45 组 |

### 4.2 提炼机制：从个案到方法

新知识不是"写下来"就进库，要经过提炼：

```
个案（一次真实文本）
   │ ① 抽取：变化是什么
   ▼
差分条目（前后原句 + 排除假变化）
   │ ② 泛化：这类变化意味着什么
   ▼
方法（操作化步骤 + 适用边界 + 判据）
   │ ③ 复现：在别的文本上还能用吗
   ▼
入方法库（编号 80+，带实例）
```

**入不了第③步的，只能留在差分表里，不进方法库。**

### 4.3 月度蒸馏：知识库的版本管理

每月执行一次，输入三样：**上月全部日报 + 对照上一版框架 + 全部新增差分与误判**。

产出四样：

| 产出 | 内容 |
|---|---|
| 方法库增量 | 新增方法（带操作化与实例） |
| 差分增量 | 新增措辞对照 |
| 轴与链变更 | 新轴、合并、退役 |
| 框架新版本 | 带版本号、生效日、**回退指针** |

**版本化不是形式**：每次改动都能回答"这一版和上一版差在哪、为什么改、改错了退回哪"。目前迭代到第六版，目录里六个历史版本全部可回退。

### 4.4 反腐化规则（比增长规则更重要）

知识库的主要死法不是不够多，是**膨胀到不可用**。四条退役规则：

| 对象 | 退役条件 |
|---|---|
| 战略轴 | 连续 60 天无新节点 / 被其他轴吸收 / 判据全部兑现完毕 |
| 方法 | 在 3 个以上场景被证明不适用 → 限定边界，而非删除 |
| 主题词 | 与已有词重合 → 合并，禁止同义并存 |
| 差分 | 被更一般的方法吸收 → 降为方法的实例 |

**宁可 18 条轴管用，不要 40 条轴摆着。**

## 5. 可观测的质量指标

不设评分卡，但设**可统计的过程指标**——过程比分数诚实：

| 指标 | 定义 | 当前做法 |
|---|---|---|
| 判据覆盖率 | 有判据的判断 / 全部判断 | 目标 100%，观察清单强制 |
| 兑现率 | 到期判据中兑现的比例 | 逐日核对，按月汇总 |
| 误判归档数 | 进档案的失败案例数 | 只增不减（现有 5 例） |
| 口径违规数 | 缺时点/跨源混算的读数条数 | 每期自查，出现即标红 |
| 差分有效数 | 有对照组且带判据的差分组数 | 45 组，逐条可查 |

**为什么不做单一分数**：一个 87 分说明不了任何事——是判据写得松、还是样本太容易，看不出来。过程指标能定位到环节。

## 6. 已知失效模式

| 失效 | 表现 | 缓解 |
|---|---|---|
| 看多了 | 把噪音当信号（主要风险） | 四条自检：谁说的/什么口径/对照组在哪/能否证伪 |
| 单日幻觉 | 只有一天文本仍硬做差分 | 硬规则：无对照不做结论 |
| 数据腐化 | 坏值、冻结序列、源偏差 | 四道闸 |
| 知识膨胀 | 轴与方法无限增长 | 退役规则 + 受控词表 |
| 自证循环 | 用自己昨天的判断印证今天的判断 | 强制外部对照（互证表的分歧格、异源数据） |
| 过度解读动机 | 从措辞直接跳到心理 | 不写动机写措辞 |

**这张表本身也是活的**：每出现一个新失效模式，就加一行，并配一条新规则。
